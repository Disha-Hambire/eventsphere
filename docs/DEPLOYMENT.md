# Deployment & Troubleshooting

## Option A: Docker (whole stack, one command)
```bash
cp .env.example .env        # edit secrets; add GEMINI_API_KEY if you have one
docker compose up --build
```
- App: http://localhost:3000 · API: http://localhost:8080 · Swagger: http://localhost:8080/swagger-ui.html
- MySQL is exposed on **3307** (so it doesn't clash with a local MySQL on 3306).
- Reset everything (including data): `docker compose down -v`
- Port 8080 busy? Put `BACKEND_PORT=8082` in `.env`. Port 3307 busy? Set `MYSQL_HOST_PORT`.

## Option B: Render (cloud)

Render hosts the API (Docker web service) and the React app (static site). **Render has no managed MySQL**, so use
an external MySQL. Free options: **Aiven for MySQL** (free plan) or **Railway**.

1. **Create a MySQL database** (Aiven: *Create service → MySQL → Free plan*). Note host, port, user, password.
   JDBC URL format:
   `jdbc:mysql://HOST:PORT/defaultdb?sslMode=REQUIRED`
2. **Push the repo to GitHub.**
3. **Render → New → Blueprint** → select the repo. `render.yaml` creates:
   - `eventsphere-api` (Docker, `/actuator/health` health check)
   - `eventsphere-web` (static site; `VITE_API_URL` is wired to the API host automatically)
4. Fill the secret env vars on `eventsphere-api`: `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, optionally `GEMINI_API_KEY`.
   `JWT_SECRET` is generated by Render.
5. If your static site gets a different URL than `https://eventsphere-web.onrender.com`, update
   `CORS_ALLOWED_ORIGINS` on the API to that exact origin.
6. Deploy. Flyway creates the tables on first boot, and demo data is seeded (set `SEED_DEMO_DATA=false` to skip).
7. **CI/CD:** in each Render service copy *Settings → Deploy Hook* and add them as GitHub secrets
   `RENDER_BACKEND_DEPLOY_HOOK` and `RENDER_FRONTEND_DEPLOY_HOOK`. Every push to `main` then runs tests →
   builds images → deploys.

> No external DB yet? For a quick demo you can set `SPRING_PROFILES_ACTIVE=h2` on the API. It runs on an embedded
> database, but data is lost on every restart of a free Render instance.

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `DB_URL` | `jdbc:mysql://localhost:3306/eventsphere?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true` | JDBC URL |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / `root` | DB credentials |
| `DB_POOL_SIZE` | `10` | Hikari pool size (use ≤ 5 on free DB tiers) |
| `JWT_SECRET` | dev value | HS256 key, **≥ 32 chars**, must be set in production |
| `JWT_EXPIRY_HOURS` | `8` | Token lifetime |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173,http://localhost:3000` | Comma-separated front-end origins |
| `GEMINI_API_KEY` | empty | Enables Gemini; empty = built-in fallback |
| `GEMINI_MODEL` | `gemini-2.5-flash` | Model id |
| `GEMINI_TIMEOUT_SECONDS` | `30` | AI call timeout |
| `MAIL_HOST` / `MAIL_PORT` / `MAIL_USERNAME` / `MAIL_PASSWORD` | empty / `587` | SMTP for reset e-mails (e.g. Gmail + app password) |
| `MAIL_FROM` | `EventSphere <no-reply@eventsphere.app>` | Sender address (with Brevo: a verified sender) |
| `BREVO_API_KEY` | empty | Send e-mail via Brevo's HTTPS API; takes priority over SMTP. **Required on Render's free plan, which blocks SMTP ports 25/465/587** |
| `PASSWORD_RESET_DEMO_MODE` | `true` | Without SMTP, show the reset code on screen. **Set `false` on a public site** |
| `PASSWORD_RESET_EXPIRY_MINUTES` | `10` | Reset code lifetime |
| `BACKEND_PORT` (docker-compose) | `8080` | Host port for the API container |
| `ADMIN_EMAILS` | empty | Comma-separated e-mails that become admins (at startup and at sign-up); no password handling |
| `DISABLE_DEMO_ACCOUNTS` | `false` | `true` deactivates the demo accounts (their passwords are public); demo events stay |
| `VITE_SHOW_DEMO` (frontend build) | empty | `true` shows one-click demo logins in a production build (always shown in `npm run dev`) |
| `SEED_DEMO_DATA` | `true` | Seed demo data when the DB is empty |
| `APP_TIMEZONE` | `Asia/Kolkata` | Zone for event times |
| `PORT` | `8080` | HTTP port (Render sets it) |
| `SPRING_PROFILES_ACTIVE` | none | `h2` = embedded DB, no MySQL needed |
| `VITE_API_URL` (frontend, build time) | empty | API base URL or host; empty = same origin |
| `VITE_PROXY_TARGET` (frontend dev) | `http://localhost:8080` | Where the Vite dev server forwards `/api` |

## Production troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Port 8080 was already in use` | Another app (e.g. Tomcat) on 8080 | `PORT=8081 mvn spring-boot:run` and set `VITE_PROXY_TARGET=http://localhost:8081` in `frontend/.env.local` |
| `Access denied for user 'root'@'localhost'` | Wrong MySQL password | Set `DB_USERNAME`/`DB_PASSWORD`, or run with the `h2` profile |
| `Communications link failure` | MySQL not running / wrong host or port | Start MySQL (`net start MySQL80`), check `DB_URL`; in Docker use host `mysql`, not `localhost` |
| `Public Key Retrieval is not allowed` | MySQL 8 auth without SSL | Keep `allowPublicKeyRetrieval=true` in `DB_URL` (local only) |
| Aiven/cloud DB: SSL errors | SSL required | Use `sslMode=REQUIRED` in `DB_URL` |
| `JWT_SECRET must be at least 32 characters` | Secret too short | Use `openssl rand -base64 48` |
| Flyway `Validate failed: checksum mismatch` | A migration file was edited after being applied | Never edit applied migrations; add `V2__...sql`. In dev only: drop the DB and restart |
| Browser: `CORS policy` error | Front-end origin not allowed | Add the exact origin (scheme + host + port) to `CORS_ALLOWED_ORIGINS` |
| Front end shows "Cannot reach the server" | API down or wrong `VITE_API_URL` | Check `/actuator/health`; rebuild the static site after changing `VITE_API_URL` (it is baked in at build time) |
| Refreshing `/events/3` gives 404 on Render/nginx | SPA routing | Keep the rewrite `/* → /index.html` (in `render.yaml` and `nginx.conf`) |
| First request on Render takes ~50 s | Free instance sleeping | Expected on the free plan; open the app a minute before the demo |
| AI shows "built-in writer/analyser" | No/invalid key, quota or timeout | Check `GEMINI_API_KEY`; server log shows `Gemini call failed … 401/429` |
| Reset e-mail never arrives on Render free plan | Free web services block SMTP ports | Use `BREVO_API_KEY` (HTTPS) instead of `MAIL_HOST` |
| Reset e-mail never arrives | SMTP not configured or rejected | Check the server log (`Could not send password reset email…`); for Gmail use an *app password*, not your normal password |
| QR scanner: "Camera unavailable" | No permission or page not on HTTPS | Allow camera; browsers only allow cameras on `https://` or `localhost`. Use manual code entry as fallback |
| Times off by hours in the cloud | Server runs in UTC | Set `APP_TIMEZONE` (defaults to Asia/Kolkata) |
| `OutOfMemoryError` on a small instance | Heap too large for the container | `JAVA_OPTS=-XX:MaxRAMPercentage=70` (already the default in the image) |
| A user's new role doesn't apply yet | Role checks use the role inside the JWT | The user logs out and in again. (Deactivation is immediate: the account is re-checked in the DB on every request.) |
